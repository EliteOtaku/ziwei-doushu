## 三、硬约束（这些从世界知识推不出来，必须遵守）

我们的实测结论，违反任何一条都会导致功能直接失效：

### 3.1 提示词会以「单条 user 消息」的形式发出

当前通道（智谱 GLM-5.3-Flash 的本地反代）**拒绝 `role: 'system'`**，会返回 405 / `code 3012 unusual activity`，报错里完全不提 system，极难定位。

所以代码里会把 system 提示词**折叠进第一条 user 消息**，实际发给模型的是：

```
{system 提示词全文}

---

{用户问题}
```

**这意味着：你写的提示词不能依赖「系统指令 vs 用户输入」的分层。** 模型看到的是一整段 user 消息。

### 3.2 输出长度必须在提示词里显式封顶

该通道对「分多段详细分析」这类**不封顶**的输出要求会只思考不产出正文。实测对照：

| 提问方式 | 结果 |
|---|---|
| 「请生成命格总览，按结构输出：命格定性/主星解读/三方四正/当前大限/优势与注意」（不封顶） | 90 秒内正文 **0 字** |
| 同一问题 + 「总长控制在 400 字内」 | 68 秒出 **429 字**完整回答 |
| 「请用三段分析，每段两三句话」 | 50 秒出 485 字 |
| 「请用 200 字说明命盘特点」 | 18 秒出 215 字 |

**该通道忽略 `max_tokens` 参数**（设成 8 也不截断），所以只能靠提示词里的自然语言约束。

**请在你产出的每一条提示词里都带上明确的字数上限**，建议 400–600 字。

### 3.3 思考阶段无法关闭

该通道强制思考，`reasoning_effort` 接受但不生效，`thinking:{type}` 直接 400。思考过程不下发前端，用户只看到「AI 正在思考… 已 N 秒」。正常出字耗时 10–90 秒。

**所以提示词越短、要求越聚焦，出字越快。**

### 3.4 会注入真实原话，模型必须逐字引用

我们有一份语料：`docs/tianji-ziwei/` 里 **1849 条**倪海厦《天纪》原话，100% 带三级标签和逐秒视频链接，格式如：

```
- [00:00:32](bilibili链接) 「我们又名叫做英星入庙迁移，英星入庙成格迁移」　<sub>格局 › 一、必定成格（吉格） · 将星得地</sub>
```

计划在做**检索增强**：按命盘特征召回 6–8 条相关原话，注入提示词。所以提示词里需要有一段专门约束引用行为。

**重要实测**：即使明确要求「只能引用以下材料」，模型仍会输出语料中查不到的引文。所以提示词层面的约束**必须写得非常硬**，同时代码层还会做后置校验兜底。

### 3.5 不要依赖模型的世界知识

模型对倪海厦体系只有模糊印象，真实依据必须来自：① 我们注入的原话；② 注入的命盘数据；③ 仓库里开源的规则库（`lib/ziwei/patterns.ts` 1119 行格局规则、`lib/ziwei/heming-knowledge.ts` 329 行合盘知识、`lib/classics/` 古籍原文）。

提示词要引导它**优先使用给定材料**，而不是自由发挥。

## 四、现有提示词（请批评并重写）

### 4.1 单人解读 system prompt

文件：`lib/ai/prompts.ts` → `buildInterpretSystemPrompt()`

```
你是一位精研倪海厦《天纪》紫微斗数的命理师，从事命理咨询二十余年。

## 你的方法论
- 以倪海厦体系为正宗：重命宫、身宫、三方四正、大限流年的星曜组合与四化引动。
- 强调「宫位互参」：看一件事不能只看单一宫位，必须同时看它的三方四正与对宫。
- 夫妻宫必兼看福德宫；财帛宫必兼看官禄宫与田宅宫。
- 星曜要结合亮度（庙旺得利平不闲陷）判断。庙旺的凶星、落陷的吉星，结论完全不同。
- 空宫借对宫主星论断，但要说明「借来的力量打折」。
- 四化是重点：生年四化看先天格局，大限四化看这十年，两者落在哪一宫就主哪方面动。

## 你必须避免的
- 不用纯飞星派的复杂飞化推演（来因宫、多重叠化、宫干自化的连环追索）。
- 不堆砌术语却不解释。术语第一次出现时用一句话说明它的意思。
- 不给运势打分式的一二三排名，而是讲清楚机制和倾向。

## 表达要求
- 用简体中文，语气沉稳专业，像面对本人面谈，不用网络流行语和过度恭维。
- 严格以提供的命盘数据为准。盘上没写的星曜、四化、宫位，一律不要提及或假定。
- 每一条判断都要落到具体依据上：哪一宫、哪颗星、什么亮度、什么四化、是否落三方四正。
- 避免绝对化预言。健康、寿元、重大灾祸只作「留意方向」表述，并提示以医生诊断为准。
- 不使用 markdown 表格；用【小标题】分段，段落之间留空行。

## 命盘数据
{formatChart() 生成的命盘文本}
```

### 4.2 六个话题的用户提问（前端 `components/InsightPanel.tsx` 的 `TOPIC_PROMPTS`）

每个都是「请生成/深度分析 X，按以下结构输出：**【小标题】** + 一句话要求」的形式，要求 4–5 个分节。例如 overview：

```
请生成命格总览，按以下结构输出：

**【命格定性】**
用一句话概括这个命盘的核心格局与命主气质。

**【主星解读】**
命宫主星的核心特质，引用倪海厦原话或观点。

**【三方四正】**
财、官、迁三宫的联动分析及整体格局。

**【当前大限】**
当下大限运势方向与最值得关注的事项。

**【优势与注意】**
命盘天赋优势，以及需要注意的风险或功课。
```

其余五个话题（love / career / wealth / health / personality）结构类似，分节要求分别是：
- love：感情格局 / 夫妻宫分析 / 三方联动 / 当前大限感情运 / 实际建议
- career：事业格局 / 官禄宫分析 / 财帛宫联动 / 当前大限事业运 / 实际建议
- wealth：财运格局 / 财帛宫分析 / 田宅宫（财库）/ 当前大限财运 / 理财建议
- health：疾厄宫主星 / 主要风险 / 大限健康走势 / 预防建议
- personality：命宫主星性格 / 三方性格综合 / 人际关系模式 / 优势与人生课题

**已知问题**：这些提示词**没有字数上限**，正是 3.2 里「90 秒 0 字」的直接诱因。而且第 42 行写着「引用倪海厦原话或观点」——在注入原话之前，这等于逼模型编造。

## 六、评判标准

你的产出会被这样检验：

1. **能不能跑通**：用改写后的提示词，在该通道上必须能在 90 秒内产出正文（不能「只思考不出字」）
2. **有没有编造**：输出里出现的每条 `「…」` 引文，必须能在注入材料中逐字找到
3. **有没有幻觉**：不得出现命盘上没有的星曜、四化、宫位
4. **是不是落到了依据**：每条判断要能指出「哪一宫、哪颗星、什么亮度、什么四化、是否落三方四正」
5. **字数是否可控**：不超过提示词里声明的上限
